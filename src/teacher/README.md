# src/teacher — AI 教官（学习状态监控）

从参考项目 `参考项目/AI_Teacher/`（Python + DeepSeek 视觉模型）移植到 C++/Qt 的版本。
启动方式：桌宠右键菜单「AI 教官（学习）」一键启动（默认配置），或设置窗口第 7 页
「AI 教官」详细配置后启动。

## 三级漏斗（对齐参考实现的实测结论）

```
L0 本地层 · 零成本，拦掉大部分采样
    屏幕已锁定（OpenInputDesktop）        → 分心（立即告警）
    连续 N 帧确认无人（肤色占比兜底）      → 分心（立即告警）
    其他一切（含人在场）                   → 交给模型判断桌面内容
    ↓ 存疑样本才继续
L1 视觉模型层 · 截图 + 摄像头合成一张图，只发一次请求
    detail=low / 关思考 / 极简提示词 / 600 次预算护栏
    ↓
L2 决策层 · EWMA + 连续 N 次才告警 + 自适应采样间隔（60s→300s）
    ↓
    告警（托盘通知 + 提示音，由 app 层发）
```

## 为什么本地只判「人不在」

「画面活跃」≠「在学习」（打游戏时画面同样剧烈变化，本地规则区分不了）；
「画面固定」也可能在思考。所以本地只保留确定性事件（锁屏、确认无人），
其余一律让模型看屏幕到底在干什么。

## 与参考实现的差异（有意为之）

| 项 | 参考实现（Python） | 本实现 |
|---|---|---|
| 语言/依赖 | Python + opencv + mss + httpx | 纯 C++/Qt，零第三方库 |
| 截屏 | mss | Win32 GDI（BitBlt）；其他平台 queued 回 GUI 线程调 QScreen |
| 摄像头 | opencv VideoCapture | Media Foundation（避免 Qt Multimedia 的 ~90MB FFmpeg 后端） |
| HTTPS | httpx | QNetworkAccessManager（无 OpenSSL DLL 时自动走系统 Schannel） |
| 人脸检测 | Haar 级联 + 肤色兜底 | **只做肤色兜底**（不引 OpenCV；Haar 在俯拍低头场景本就漏检，肤色通道正是兜它的） |
| 记录 | SQLite sessions.db + 日志文件 | 进程内统计 + qInfo；**图片不落盘、不记 key/请求体** |
| 累计休息时长 | （有个 bug：加的是切换后的专注时长） | 修正为休息阶段真实时长 |

## 线程模型

`TeacherMonitor` 本身是 `QThread`。截图、摄像头、HTTP 都是阻塞操作，必须离开
主线程。**平台资源（GDI / MF / COM）在 run() 里出生、在 run() 里销毁**——MF 的
COM 实例有线程亲和性，跨线程构造析构会崩。`judge()` 用嵌套事件循环同步等结果，
内部 200ms 轮询一次「停止监控」，点停止不用干等满一个 HTTP 超时。

`QNetworkAccessManager` 懒创建于监控线程（QObject 线程亲和性），跨 tick 复用连接。

## 隐私

- 图片默认不落盘，只把判定结果（文字 + 数字）广播给 UI
- 摄像头画面是否上传由 `uploadCamera` 控制：关掉仍本地做肤色检测（不花钱、不外传）
- 日志只记字节数，**绝不记录 API key、图片内容、请求体**
- 监控只在用户显式启动后运行；不启动时本模块完全不活动（无摄像头、无截屏、无网络）

## 成本（DeepSeek 实测口径）

单次判定约 276 输入 + 14 输出 token ≈ ¥0.0003~0.0007（高峰/空闲差 2 倍）。
自适应间隔下持续学习一天（8h）约 128 次调用 ≈ ¥0.04~0.09。
「越不学习越费钱」是合理的：判定「你在学」需要密集采样来确认。

## 实测验证记录（2026-10-12，Windows / Qt 6.11.2）

- **无 key 冒烟**（`Pic2Pet.exe --teacher`，跑 75s）：正常启动、tick 1/tick 2 严格按
  60s 间隔执行；工作线程 BitBlt 截屏稳定无崩；内存无泄漏迹象（~243–261MB 含 150MB 帧内存）
- **无摄像头降级**：本机摄像头被占用 → 日志「摄像头不可用…将仅凭屏幕判定」，监控继续
- **HTTPS 全链路**（指向 api.deepseek.com + 假 key）：TLS 握手 → 请求 → 收到 http_401 →
  「模型不可用：http_401」优雅降级，监控不崩不停。证明无 OpenSSL DLL 时 Schannel 回退可用
- **界面**：设置窗口第 7 页渲染正常（状态卡 + 启动/停止按钮 + 目标 + 会话/花费 + 接口/模型/Key
  + 采集开关 + 番茄钟 + 隐私说明）
- **分发**：`dist/` 保留 Qt6Network.dll(1.75MB) + tls/qschannelbackend.dll(248KB)，
  裁剪后共 32MB / 11 项，exe 启动正常
